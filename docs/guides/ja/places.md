`<chikyu-space>` と `<chikyu-earth-realistic>` は、地球の上に場所の目印を出せます。読む人が今いる場所と、その人が残しておきたい場所です。目印は地面から立ち上がる小さな形で、地球といっしょに回り、地球の裏側に回ると隠れます。ズームしても画面の上での大きさ (ピクセル) は変わりません。

```html
<chikyu-space
  places='[{"id":"me","lon":139.69,"lat":35.69,"label":"現在地","kind":"here"},{"id":"osaka","lon":135.5,"lat":34.69,"label":"大阪"}]'
  places-look="beam"
  style="width: 420px"
></chikyu-space>
```

| 属性 | プロパティ | 意味 |
|---|---|---|
| `places` | `places` | 場所の JSON 配列です。それぞれ `{ id, lon, lat, label, kind, color }` の形で、あとから説明する `layer`、`size`、`look`、`namePriority` も付けられます。プロパティを設定すると属性に書き込まれ、空の配列にすると属性が消えます。 |
| `place-layers` | `placeLayers` | 層の名前に true か false を対応させた JSON オブジェクトです。例: `{"harbours":false}`。出す層と隠す層を決めます (「場所の層」を参照)。 |
| `places-look` | `placesLook` | `beam` (初期値): 地面から立ち上がる光の柱と、その根元の輪です。`pin`: 細い棒と丸い頭です。`ring`: 地面の輪だけです。 |
| `here-city` | `hereCity` | 初期値はオフ (`false`) です。属性を付けるか `on` にすると、`here` の場所に、100 キロメートル以内でいちばん近い都市の名前が付きます。数字はその上限のキロメートルです。プロパティを `false` にするとオフになります。 |

- **種類。** `kind: "here"` は読む人が今いる場所で、背が高く、明るく、根元の輪がゆっくり広がります。ほかの場所はすべて `favourite` (お気に入り) で、背が低く、細く、動きません。色は要素かページの `--chikyu-place-here` と `--chikyu-place-favourite` で変えられます。
- **場所ごとの色。** `color` で、場所ごとに自分の色をつけられます。16 進の色 (`#e8475f`)、数字で書いた `rgb()` か `hsl()`、または色の名前です。それ以外は使わず、種類の色になります。
- **地面から立ち上がる。** 目印は、画面から見た地面に対して上向きに立ちます。地球のふちの近くでは横にかたむき、根元の輪はほとんど横から見た形になります。真上から見る場所では、点につぶれないように画面の上のほうへかたむきます。
- **名前。** 場所の `label` は、すき間があれば目印の上に出ます。`here` が先で、あとは渡した順です。名前どうしは重ならず、宇宙の見た目では天体の名前とも重なりません。置く場所がない名前は出しませんが、目印は描きます。場所は、各層の名前のなかで最初に置かれます。目印のラベル、都市の名前、星と星座の名前は、場所の名前、場所の目印、輪を付けた衛星を避けます。逆はありません (空の名前の guide の「層の順序」を参照)。名前の大きさは、ページのフォントで実際に測ります。
- **夜は暗めに。** 地球の夜の側にある場所は半分の明るさで描き、名前は読めるように、少しだけ暗くします。夕方や明け方はその間です。`light="lit"` のときは地球全体が明るいので、暗くしません。
- **止まっているときは何もしない。** 場所の配置は、絵を描くとき (カメラが動いた、時計が進んだ、設定が変わった) だけ計算します。輪が広がる動きは CSS のアニメーションなので、絵を描き直すことはありません。要素が見えないあいだは止まり、動きを減らす設定の人には出ません。
- **最大 5,000 か所。** それより長い配列は `MAX_PLACES` までに切ります。経度が -180 から 180 の外、または緯度が -90 から 90 の外にある場所は出しません。

## たくさんの場所

ページは何千か所でも渡せて、それでも重くなりません。

```js no-run
const places = shops.map((shop) => ({ id: shop.id, lon: shop.lon, lat: shop.lat, label: shop.name, color: shop.open ? "#7dd3fc" : "#94a3b8" }));
space.places = [...(here ? [here] : []), ...places];
```

- **最初のいくつかは立つ目印。** 見えている場所のうち最初の `PLACE_MARKS` (32) か所は、`here` が先で、あとは渡した順に、名前といっしょに地面から立ち上がります。いちばん大事な場所を先に置いてください。
- **ほかは 1 回の描画。** ほかの場所はすべて地面に置いた輪になり、いくつあっても 1 回の描画 (draw call) でまとめて描きます。輪も目印と同じく、画面の上での大きさが変わらず、地球といっしょに回り、ふちでうすくなり、裏側では出ず、夜の側では暗めになります。
- **混み合う場所はまとめる。** 画面の上で約 `PLACE_GROUP_PX` (24) ピクセルより近い場所は、少し大きい 1 つの輪になり、横に数が出ます。ます目は地面に固定しているので、まとまりは地球といっしょに回り、ズームが約半分か約 2 倍になったときだけ変わります。ズームインすると分かれます。読む人の現在地はまとめません。同じ決まりを、ページやサーバーでも `groupPlaces` と `groupCell` で使えます。まとめるのが初期設定です。`place-groups="off"` (またはプロパティ `placeGroups = false`) にすると、まとめずに、場所ごとに 1 つずつ輪を出します。
- **どれだけ描いたか。** `stats.places` には、`places` (渡した数)、`hidden` (層がオフで外れた数)、`shown` (見えている数、まとまりの中も数える)、`marks` (目印として立つ数)、`labels` (名前の数)、`sprites` (絵の 1 回の描画で描く輪の数。絵が輪を描けないときは 0)、`dots` (その代わりに、ページの中の小さい円として描いた輪の数)、`groups` (輪のうち、まとまりの数)、`omitted` (見えているのに、描く余地がなくて描けなかった場所の数)、`renders` (配置を計算した回数) があります。three.js の `Points` がないとき (`Points` を含まない一部だけを渡したとき) は、絵の中に輪を描けないので、要素が自分で、輪を小さい円としてページの中に描きます (最大 `PLACE_DOTS` (600) 個)。その円は、絵の中の輪と同じように、地球の縁で薄くなり、夜は暗くなります。それを超えて見えている場所は `omitted` に数え、そのときだけ `chikyu-places-unavailable` を 1 回送ります (`detail.reason` に理由、`detail.omitted` に数が入ります。`Points` がないだけでは送らず、二度は送りません)。数えられないまま消える場所はありません。

## 場所を押す

視点を回さない押し方で、場所の目印 (棒か根元) や輪を押すと、`chikyu-place-click` が届き、その場所の `id` と `kind` がわかります。ページが目印の枠を読む必要はありません。

```js no-run
space.addEventListener("chikyu-place-click", (event) => {
  const { id, kind, layer, label, lon, lat, x, y } = event.detail;
  console.log(id, kind, layer, label, lon, lat, x, y);
});
```

- **届く内容。** `id` と `kind` (`here` か `favourite`) はいつも届きます。ほかに `layer`、`label`、`lon`、`lat`、`x`、`y` (押した位置。要素の中の CSS ピクセル) が届きます。対象は、直前の絵に描いた場所です。層がオフの場所や、地球の裏側の場所は押せません。配列や層のスイッチが変わってから次の絵になるまでのあいだも、押せません。
- **12 ピクセル以内でいちばん近い場所。** 目印は、根元から先までの棒のどこを押しても反応し、輪も反応します。複数の場所をまとめた輪は 1 つの場所ではないので、何も届きません。この押し方は、これまでどおり `chikyu-satellite-click` や `chikyu-body-click` にもなります。このイベントは足されるだけで、何も取りません。衛星の点のほうが先に反応します。
- **止まっているときは何もしない。** 場所は、読む人が押したときに、直前の絵の内容から探します。それ以外のときは探しません。

## 場所ごとの見た目と大きさ

場所を 1 つずつ別の見た目にできます。たとえば港は都市より短い目印にして、「現在地」は背の高い光の柱のままにできます。

```js no-run
space.places = [
  { id: "me", lon: -79.4, lat: 43.7, label: "現在地", kind: "here" },
  { id: "cavan", lon: -123.1, lat: 49.29, label: "バンクーバー港", size: "small", look: "ring" },
];
```

- **`size: "small"`** は、その種類の標準より棒が約半分の長さ、輪が約 3 割小さくなります。何も書かなければ、種類の標準の大きさです。
- **`look`** は `beam`、`pin`、`ring` のどれかで、その場所だけ `places-look` より優先されます。書かなければ `places-look` になります。

## 場所の層

場所に `layer` (自分で決めた名前。40 文字まで) を付けて、`place-layers` で層ごとに出したり隠したりできます。スイッチごとに配列を作り直さず、ページは配列を 1 回渡すだけです。

```js no-run
space.places = [...spaceports.map((p) => ({ ...p, layer: "spaceports" })), ...harbours.map((p) => ({ ...p, layer: "harbours", size: "small" }))];
space.placeLayers = { harbours: false };
space.setPlaceLayer("harbours", true);
```

- **オフにしないかぎり出ます。** `layer` のない場所は、いつも出ます。`place-layers` に書いていない層も出ます。隠れるのは `false` の層だけです。`placeLayers` でスイッチの状態を読め、`setPlaceLayer(name, shown)` は 1 つの層だけを変えて、ほかはそのままにします。
- **まるごと外れます。** オフの層の場所は、描かず、名前も出さず、まとめの輪にも入れず、押しても反応せず、`PLACE_MARKS` の数にも入りません。外れた数は `stats.places.hidden` に出ます。`stats.places.places` は、これまでどおり渡した数です。`readPlaceLayers` と `shownPlaces` は、ページやサーバーで同じ決まりを使うためのものです。
- **何も取りに行きません。** パッケージは、層のために何も読み込みません。スイッチがオンになったときに場所を取ってくるのは、ページの仕事で、取れたら渡してください。

## 都市の名前にゆずる名前

場所の名前は、都市の名前より先に置かれ、都市の名前が場所の名前を避けます。`namePriority: "low"` の場所はその反対です。名前は都市の名前のあとに置かれ、都市の名前がある場所では名前を出しません。目印は描きます。

```js no-run
space.places = [{ id: "cape-canaveral", lon: -80.58, lat: 28.39, label: "ケープカナベラル", layer: "spaceports", namePriority: "low" }];
```

- **都市のあと、ほかの名前の前。** 海や国の名前、星の名前は、`low` の名前が置かれたあとは、ほかの名前と同じようにそれを避けます。
- **都市が先。** `city-names` がオンのとき、都市の名前は、そこに場所がないときと同じ位置に残ります。場所の名前は、残ったすき間に置かれ、すき間がなければ出ません。`city-names` がオフなら、ゆずる相手がないので、ほかの名前と同じように置かれます。
- **止まっているときは何もしない。** `low` の名前も、ほかの名前と同じ絵のなかで置かれます。置き直すのは、都市の名前が変わったときだけです。

## 場所へ向ける

`goToPlace` は、場所が真ん中に来るように見る向きを回します。目で追える速さで回り、動きを減らす設定の人にはすぐに切り替わります。場所は `id` か名前 (`label`) で指定します。

```js no-run
const place = await space.goToPlace("tokyo");
if (!place) console.log("その場所はありません");
```

- **ズームはそのまま。** 変わるのは向きだけです。ズームしたいときはページがします。
- **地球を見ているとき。** 宇宙の見た目では、カメラが地球を見ている必要があります。ほかの天体といっしょに移動しているときや、ほかの天体を見ているときは何も動かず、`undefined` が返ります。
- **かたむきは 90 度まで。** ドラッグと同じく、`center` から上下に 90 度までです。`center` から緯度で 90 度より離れた場所は、その範囲でできるだけ真ん中に近づけます。`center` は読む人の現在地の近くにしてください。
- **新しい場所へは、曲がって向かう。** 回っているあいだに `goToPlace` をもう一度よんでも、止まってやり直すことはありません。今の速さと向きのまま、なめらかに新しい場所へ曲がっていきます (どちらの要素でも同じです。宇宙の見た目では `flyTo` とのあいだでも同じです)。

## 場所へ飛ぶ

宇宙の見た目では、`flyTo(lat, lon, options)` でカメラを場所へ運べます。動きは二つに分かれます。まず**横へ**: 今の高さのまま地球を回して、場所を真下に持ってきます (大円にそって動きます)。次に**下へ**: その場所の上 `height` キロメートルまで下ります (ふつうは 30 km。都市がまるごと見えて、30 m の細かい写真でもくっきりした高さです)。動きが終わると結果が返ります。

```js no-run
const space = document.querySelector("chikyu-space");
space.setAttribute("tiles-finer", "gibs");
const end = await space.flyTo(35.69, 139.69, { height: 30 });
console.log(end.reason, Math.round(end.heightKm), end.held); // "arrived" 30 null
```

- **一つずつ動かせる。** `phase: "across"` は横へだけ、`phase: "down"` は下へだけ、`"both"` (ふつう) は横へ動いてから下ります。ページは、読む人が押すたびに一つずつ進められます。
- **新しい動きは、今の動きを曲げる。** 動いているあいだに `flyTo` や `goToPlace` をよんでも、急に止まることはありません。カメラは今の速さと向きのまま、新しい道へなめらかに曲がります。下りている途中なら、引き返さずにゆっくり止まってから横へ動きます。引きつがれたほうの動きは `"redirected"` で終わります。
- **手でさわると、その場で止まる。** ドラッグ、ピンチ、ホイール、キー、または `signal` (`AbortSignal`) で、その場ですぐ止まり、`"stopped"` で終わります。天体といっしょに動きはじめたときや、要素がページから外れたときも同じです。
- **写真がくっきりしなくなる高さで止まる。** 最後まで下りるのは、`tiles-finer` がオンで、南緯 60 度から北緯 80 度までの陸の上だけです。細かい写真があるのはそこだからです。海、南極、北のはて、または `tiles-finer` がないときは、パッケージの写真がくっきり見える 400 km (`FLY_FLOOR_KM`) で止まり、`held` は `"no-finer"` になります。ページが決めた `zoom-max` でも止まります (`"zoom-max"`)。15 km (`FLY_MIN_KM`) より下には行きません。
- **ズームもついてくる。** 一度 約 320 km より下まで来ると、ズームもそこまで届くようになります。読む人はズームで離れて、また近づけます。ビューが自分で回る動き (Auto-turn) は止めます。場所が真下からずれないようにするためです。
- **動きを減らす設定。** 動きを減らす設定の人、`smooth: false`、まだ絵が出ていないときは、高さもふくめて、すぐにその場所へ切り替わります。
- **イベントと stats。** 始まると `chikyu-fly-start` (`{ lon, lat, phase, heightKm, held }`)、終わると `chikyu-fly-end` (`flyTo` が返すものと同じ) を送ります。`stats.fly` で、動いているか、どちらの段階か、今の高さ、最後に下りたとき何で止まったか、いくつ引きつがれたかがわかります。止まっているあいだは何も動きません。動いているあいだも、一度に一つのフレームしか求めず、ビューのフレームの上限を守ります。
- **計算だけの部分。** `@johnmorrisdotca/chikyu-earth/space` の `planFly`、`flyAt`、`flyStateAt` が、この動きそのものです。テストや、ページ自身のカメラに使えます。向きと高さは、それぞれ、カメラの今の速さと加速度から始まる 5 次式なので、切り替わるところでも速さと向きがとぎれません。

## 読む人の現在地

パッケージがブラウザーに現在地をたずねることはありません。たずねるのはページで、読む人が求めたときだけです。

```js no-run
import { nearby } from "@johnmorrisdotca/chikyu-earth/markers";

const space = document.querySelector("chikyu-space");
document.querySelector("#here").addEventListener("click", () => {
  navigator.geolocation.getCurrentPosition((position) => {
    const at = nearby({ lon: position.coords.longitude, lat: position.coords.latitude });
    space.places = [{ id: "here", lon: at.lon, lat: at.lat, label: "現在地", kind: "here" }];
  });
});
```

- **ボタンを押したときにたずねる。** `getCurrentPosition` は読む人のクリックから呼びます。こうすると、ブラウザーの確認は本人が求めたあとに出ます。消す方法も用意してください (`space.places = []`)。
- **まるめる。** `nearby(point, km)` は、場所を約 `km` キロメートルのます目 (初期値は 10) に合わせます。目印が通りの名前までわかる位置に出ることはありません。描く前や残す前にまるめてください。
- **端末の中だけに置く。** 要素は何も保存せず、どこにも送りません。本人が共有を選ばないかぎり、現在地をページのアドレスに入れたり、サーバーに送ったりしないでください。デモは開いているページの中だけで使い、ページを閉じると消えます。

## いちばん近い都市の名前

`here-city` を付けると、`kind: "here"` の目印に、いちばん近い都市の名前がページの言語で出ます。初期値はオフです。オンになって、かつ `here` の場所があるときまで、kuni は読み込まれません。

```html
<chikyu-earth-realistic here-city places='[{"id":"me","lon":139.69,"lat":35.69,"kind":"here","label":"現在地"}]'></chikyu-earth-realistic>
```

- **頼まれたときだけ。** 初期値はオフです (`hereCity` は `false`)。お気に入りの名前は変わりません。
- **距離。** 属性だけ、または `on` のときは 100 キロメートル (`HERE_CITY_KM`) です。`here-city="40"` は 40 キロメートル以内だけを見ます。受け付けるいちばん遠い距離は 20,000 キロメートル (`HERE_CITY_MAX_KM`) です。上限より遠い都市は使わず、ページが付けた `label` のままです。
- **どの都市か。** まず首都、人口100万人の都市、人口10万人の都市です。そのあと、多くても2つの国の小さな都市を、国ごとに1つのファイル (`citiesOf`) から読みます。1つ目の国は、その3つの段でいちばん近い都市の国です。距離は問いません。2つ目は、別の国の都市も上限の内側にあるときだけ足します。国境の近くは、そうやって読みます。大きな都市より近い町があれば、そちらを出します。上限の外は使いません。kuni は、`here-city` がオンで `here` の場所があるまで読みません。名前は英語です。日本語のページでは、短い日本語名があればそれ、なければ日本語名です。
- **ページの一覧は変わらない。** `places` には、ページが設定した名前が残ります。変わるのは描かれる名前だけです。`goToPlace` は、その名前か `id` で場所を探します。
- **止まっているときは何もしない。** 名前を決めるのは、場所、言語、距離の上限が変わったときと、都市の一覧が届いたときだけです。絵が止まっているあいだは、決め直しません。

## お気に入りの場所

`kind: "here"` がない場所は、すべてお気に入りです。パッケージは自分の一覧も、選ぶための画面も持っていません。読む人の一覧はページが作り (ページ独自の検索や、kuni の都市から)、好きな所に残し、変わるたびに一覧ごと渡します。

```js no-run
const saved = [{ id: "tokyo", lon: 139.69, lat: 35.69, label: "東京" }, { id: "cairo", lon: 31.24, lat: 30.04, label: "カイロ" }];
space.places = [...(here ? [here] : []), ...saved];
```

- **一覧をどこに置くかはページが決める。** アカウントのあるサイトなら、読む人のアカウントに残します。デモは選んだ都市をページのアドレス (`fav=Tokyo,Cairo`) に残すので、リンクを開くとその都市が出ます。読む人の現在地をそこに入れることはありません。
- **現在地より控えめ。** お気に入りは背が低く、細く、動かないので、その中でも読む人の現在地が目立ちます。名前が混み合うと、`here` の名前が先に置かれます。

## ブラウザーなしで使える部分

`@johnmorrisdotca/chikyu-earth/markers` には、自分で場所を描くページやサーバー向けの計算部分があります。`readPlaces` と `cleanPlaces` (描いても安全な配列にする)、`readPlaceLayers` と `shownPlaces` (層のスイッチと、そこに残る場所)、`nearby`、`orthoView` (正面から描いた絵を、中心の点、半径、枠から作る)、`layoutPlaces` (`PlaceView` から、絵の中の目印と名前の位置を出す。`sun` を渡すと、それぞれがどれだけ夜に入っているかも出す)、`groupPlaces` と `groupCell` (地球の幅が何ピクセルかに合わせて、混み合う場所をまとめる)、`readHereCity` と `hereCityLabels` (`nearest` を持つ一覧から、`here` の場所に付けるいちばん近い都市の名前を、キロメートルの上限の中で出す) です。
